# 避難所の受付から、医師につなぐまで

災害時に避難所の受付を入口として、薬が切れた方や持病の相談を、**被災していない地域の医師**につなぐ仕組みの試作です。

👉 **[公開ページ](https://arukurac3ss.github.io/saigai-uketsuke/)**

## これは何か

避難所の受付は、名前と住所を聞きます。でも、その人が薬を切らしていることは聞きません。聞いても、次に何をするかが決まっていません。

調べてみると、被災者を登録する仕組みも、医療者どうしをつなぐ仕組みもありました。ただ、**登録された人の困りごとが医療者に流れていく経路**が見つかりませんでした。

- [なぜ作ったのか（記事）](kiji.html) — 調査・設計判断・未実装の整理
- [仕組みの説明](lp.html) — 自治体・医師会向け
- [試作を触ってみる](mock.html) — ブラウザで動きます

## 試作の動かし方

`mock.html` をブラウザで開くだけです。ビルドもサーバーも不要で、HTMLファイル1つで完結しています。通信もしません。

デモのデータが入っているので、そのまま操作を試せます。端末の役割（受付／診察／掲示／巡回）は、設定画面で切り替えられます。

深夜の交代要員がログインで詰まるのが一番怖いので、認証は入れていません。実運用では端末登録型にする必要があります。

## まだできていないこと

- **全避難所の待ち行列をサーバーで集約し、空いた医師に自動で割り当てる** — この構想の中心ですが、未実装です
- 医師の待機登録と、ワンタップでの離脱
- 二重割り当ての防止、無応答時の転送
- 同じ避難所の端末どうしの同期（いまは端末ごとに記録を持っています）
- オフラインで受けた分の後送
- 自治体システムとのCSV／API連携
- 端末登録型の認証、医師側の本人確認
- 実際の映像通話の組み込み（いまは見た目だけ）
- 番号を忘れた方の本人確認

つまり、構想の骨格しかありません。

## 先行事例について

2021年、DMATの隊員で神戸学院大学の中田敬司教授らが、避難所の方を地元の医療機関にオンライン診療でつなぎ、薬を届ける仕組みを考案されています。2020年の九州豪雨で実地に試行もされています。

この試作との違いは、**診る側を被災地ではなく被災していない地域に置くこと**と、**本人が選ぶのではなく待ち時間の長い順に自動で割り当てること**です。どちらが良いという話ではありません。

その後どうなったかを追えていません。継続している取り組みがあれば、そちらに合流すべきだと考えています。**ご存じの方がいたら教えてください。**
